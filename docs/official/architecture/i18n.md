# i18n

> 覆盖：locale 存储、翻译资源结构与各端消费方式。
> 文案迁移流程（key 命名、三语同步步骤、check 命令）见 `.agents/skills/i18n/SKILL.md`；zh-CN 逐条注释规范见根 `AGENTS.md`。
> 机制细节的权威在 `packages/i18n/src/`（catalog / translate / react 绑定）。

## 架构

- `@spherse/i18n` 纯 TS 包，两个子入口：`.`（`translate(locale, key, params)` 纯函数与类型）和 `./react`（`I18nProvider` + `useI18n()`）
- locale 是应用级设置，默认 `zh-CN`；desktop 持久化 electron-store（settings.json），web 持久化 localStorage（`spherse:settings`）
- **`zh-CN.ts` 是翻译基准**：`TranslationKey` 类型由其对象 keys 推导（不手写）；`zh-TW` / `en` 必须保持 key 集一致
- locale catalog：`src/locales/{zh-CN,zh-TW,en}.ts`；插值用 `{name}` 占位

## 消费方

- **renderer**：`I18nProvider` 挂载 locale，组件经 `useI18n()` 取 `t()`
- **Electron main**：IPC 错误 / 确认文案经 `translate(locale, key, params)`（如 project IPC、右键菜单）
- **web 壳**：版本守卫、连接页等壳级 UI 经 `translate`
- **server 与 core 不依赖 `@spherse/i18n`**：错误以结构化 code（如 chat 的 `ErrorEventCode`）传给前端，i18n 渲染决策在 renderer
- **landing 复用类型与 locale 工具**（`Locale`、`normalizeLocale`、`SUPPORTED_LOCALES`），catalog 独立维护，不与应用共享文案

## 校验与测试

- `npm run check:i18n`：三语 key 一致性 + 插值变量一致性，纳入 root `npm run verify`
- `npm test --workspace=packages/i18n`
